## 2　生成 / 补全顺序

1. **契约层**（已完成）：`schema` → `config` → `robot_api` → `executor` → `pasd_core` → `gates` → `runner` → `judge` → `metrics`。验收：`python3 scripts/run_smoke.py` 全链路通过。
2. **主表 A 补全**：`trajectory` / `episodic` / `pragmabot` / `tgl_skill`（TGL 优先，审稿人必问）。验收：四个基线跑同一 `run_episode` 不报接口错。
3. **任务层**：`task_specs` / `instructions` / `feeding` / `retrieval` + 两套任务配置；自动成功判定与自动复位。
4. **C1 证据**：`experiments/e2_library_convergence.py` 出 `|B_t|` 曲线 + 上界形式化证明写进 `paper/claims.md`。**性价比最高，先做。**
5. **C2 证据**：`safety.py` 完善 + E4 去 Gate3 消融（假人头部先做）。
6. **C3 证据**：`evaluation.py` 的 S³R 与统一日志 schema → `domain_rand.py` 离线闭环 → E6。
7. **副表 C1/C2**：按需补齐，全部标 `proxy` 与预算；`tables.py` 分表输出。
8. **真机接入**：先按 `docs/08` 第 6 节核对 SDK 六项，再实现 `backends/piper.py::PiperSDKAdapter` 与 `backends/mujoco.py::MuJoCoBackend`（补 `configs/mujoco/piper.xml`）、`ClaudeCodePolicyGenerator` 真实调用；标定摩擦与夹持力；E3/E5 真机数据。**在此之前这两个后端必须保持显式失败，不得伪造物理或电机调用。**
9. **投稿**：`paper/` 四件套 → 统计检验 → 公开配置、种子、复位脚本、日志 schema。

## 5　Linux 目录与路径契约（`docs/08`）

| 项 | 约定 |
|---|---|
| 源码 / 文档 | 仓库内相对路径，`repo_root()` 运行时解析；禁止 `D:/`、`C:/`、`/home/<user>/` 硬编码 |
| 换行 / 编码 | 所有文本 LF + UTF-8（`.gitattributes` 与 `deploy/make_dist.py` 双重保证） |
| 解释器 | `python3`（`#!/usr/bin/env python3` / `#!/usr/bin/env bash`）；`deploy/*.sh` 打包时设 `0755` |
| 运行状态 | `PASD_HOME`（默认 `${XDG_DATA_HOME:-~/.local/share}/pasd-life-assist`）下 `logs/ runs/ artifacts/`，**在仓库外** |
| 密钥 | `.env` 不入库；`doctor.py` 只报存在性；`make_dist.py` 二次排除 |
| 打包产物 | `dist/*.tar.gz` + `SHA256SUMS` + `MANIFEST.txt`，归档顶层目录恒为 `pasd-life-assist/` |
