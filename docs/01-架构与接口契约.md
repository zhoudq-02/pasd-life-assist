# 01　架构与接口契约（代码级）

> 所有签名以本文件为准。 Claude Code 扩写时**不得改名、不得删字段、不得改变调用顺序**；只能补内部实现。

## 1　统一接口协议（六项，落实文献 [5] 七(六)）

| 规范项 | 定义 |
|---|---|
| 状态表示 | 3D 场景图节点 `object_id / pose / affordance / confidence / timestamp`；规划、校验、评测共用同一 `SceneGraph` 实例 |
| 动作接口 | `RobotAPI` 五原语，SI 单位；`0.022` 表示夹住 22 mm 物体而非失败量 |
| 时间同步 | 统一 `frame_id` 与时基；控制频率显式写进任务配置 |
| 失败信号 | `error_code` + `stage`(perception/planning/execution/verification/interaction/safety) + 白名单 `features` + `description` |
| 回退触发 | 分级表：重感知 → 局部重规划 → 换策略 → 安全停机 → 请求人工 |
| 日志格式 | 全链路 `Trace` 落盘，含逐原语输入/输出/耗时/关键帧/错误码 |

防污染两条硬编码：白名单 API 禁仿真真值；dev 可写库、heldout 只记录。

## 2　核心数据结构（`src/pasd_life/schema.py`）

```python
@dataclass(frozen=True)
class Condition:            # 签名中的一条触发条件
    field: str              # 必须来自 FEATURE_WHITELIST
    op: Literal[">", "<", ">=", "<=", "=="]
    theta: float            # 经 _q_dir 有向取整后的阈值

@dataclass
class FailureSignature:     # σ
    stage: str
    error_code: str
    conditions: tuple[Condition, ...]
    description: str = ""

@dataclass
class Skill:                # ⟨σ, C, π, V⟩ 四要素技能 + 生命周期字段
    sigma: FailureSignature
    applicable: dict         # C：适用条件/上下文
    repair: dict             # π：可执行修复（含 fixes 字段，须 == error_code）
    verification: dict       # V：Gate2/Gate3 记录与次数
    identity: tuple[str, str, int]   # (stage, error_code, cluster_id)
    state: Literal["OBSERVED","CANDIDATE","VERIFIED","SAFE","REJECTED"]
    hits: int = 0
    tag: str = ""            # 任务标签，支撑向上蒸馏

@dataclass
class Trace:                # PASD 唯一输入
    task: str
    error_code: str
    message: str
    features: dict          # 只含白名单诊断特征
    scene: dict             # 仅用于在线聚类，不参与签名阈值生成
    policy: str
    split: str              # "dev" | "heldout"
    success: bool = False
    obs_refs: list[str] = field(default_factory=list)
    used_blocks: list[dict] = field(default_factory=list)
    candidate_blocks: list[dict] = field(default_factory=list)
    applied_repair: dict | None = None
    repair_segment: dict | None = None
    repair_verified: bool = False
    frame_id: int = 0

@dataclass
class SceneContext:
    instruction: str
    scene_summary: str
    split: str
    features: dict
    scene_graph: "SceneGraph | None" = None

@dataclass
class StepFeedback:
    obs_before: dict; action: dict; obs_after: dict; step: int

@dataclass
class RepairHint:           # 所有基线输出的唯一包装
    text: str
    executable: dict | None
    verified: bool
    verified_by: str        # "simulation"|"vlm_judge"|"admission_check"|"human"|"none"
    source: str
```

> `verified_by` 是 v1.1 关键修正：对照组并非都「无验证」。PRAGMABOT(vlm_judge) / TGL(admission_check) / SSS(vlm_judge) / ARMADA(human) / PASD(simulation) 各填各的。

## 3　RobotAPI 五原语（`src/pasd_life/robot_api.py`）

```python
ALLOWED = frozenset({
    "move_to_pose", "open_gripper", "close_gripper", "get_observation", "solve_ik"
})

class RobotAPI:
    def __init__(self, backend: "Backend") -> None: ...
    def call(self, name: str, **kwargs) -> dict:
        # name 不在 ALLOWED → 立即 raise WhitelistViolation（不执行）
        ...
    def move_to_pose(self, pose, speed: float) -> dict: ...
    def open_gripper(self) -> dict: ...
    def close_gripper(self, width: float) -> dict: ...   # width 单位：米
    def get_observation(self) -> dict: ...               # 只返回 REAL_OBSERVABLE_FIELDS
    def solve_ik(self, target_pose) -> dict | None: ...  # None → IK_UNREACHABLE
```

后端三选一，接口完全一致：
`MockPiPER`（标准库，冒烟测试）/ `MuJoCoBackend`（可选依赖）/ `RealPiPERBackend`（piper_sdk，可选依赖）。
缺失可选依赖时 `import` 必须包在 `try/except ImportError` 里并给出可理解的降级提示。

**PiPER 物理语义硬规则**（写进 Mock 与真机后端，不可省）：

| 现象 | 规则 |
|---|---|
| 6-DoF 无零空间 | 不做冗余角搜索；多起点阻尼最小二乘 IK + 可达性预筛；无解 → `IK_UNREACHABLE` |
| 细长物体顶抓必滑 | `aspect_ratio > 4` 且 `approach == "top"` → `GRASP_SLIP` |
| 夹爪量程 0–70 mm | `target_width > 0.070` → `GRASP_IMPOSSIBLE`，不硬夹 |
| 夹持证据 | 稳定开度 ≈ 物体宽 + 闭合电流上升超空载基线联合判定；10 mm 级分辨率足够 |
| 真机复位 | 固定料仓 / 限位工装 / 脚本化重置，任务须自动判成功且自动复位 |

## 5　闸门与安全（`gates.py` / `safety.py`）

```python
def gate1_observe_failure(trace, extractor, clusterer, library,
                          repair_fn=None) -> Skill | None
def gate2_verify(skill, sim_runner, repeats=10, threshold=0.80) -> bool
def gate3_verify(skill, real_log, consecutive=8, human_confirmed=True,
                 envelope=None, features=None) -> bool
def promote(skill, sim_runner, real_log=None, features=None,
            envelope=None, human_confirmed=True) -> Skill   # 统一状态机入口

@dataclass(frozen=True)
class SafetyEnvelope:
    min_human_dist: float; max_eef_speed: float; max_contact_force: float
    max_food_temp: float; max_tilt_angle: float; max_fill_level: float
    def violated(self, features: dict) -> tuple[bool, str]: ...
```

`promote` 是唯一允许改变 `skill.state` 的函数；其他模块只读状态。
`real_log=None` 表示**离线仿真阶段**：技能晋升到 `VERIFIED` 即停，Gate3 留到真机部署流程由 `gate3_verify` 执行。
**安全包络否决优先于 Gate2 成功率**：`if envelope.violated(features)[0]: return REJECTED`（即使 Gate2 本可达标）。

## 6　统一评测（`src/pasd_life/evaluation.py`）

- `S³R`：只有「任务完成 + 过程无未恢复失败 + 安全包络不越界 + 无危险接近」的 episode 才计成功。
- `Δ = SR − S³R`：隐性不稳定度。
- 能力剖面字段：子目标完成率、中间状态校验结果、失败位置/类型、恢复尝试次数、局部重规划成功率、执行耗时、最小人机距离、最大接触力、洒漏率。
- 日志 schema 固定，所有基线共用；`metrics.py` 是唯一指标计算入口。

## 8　统一适配层（`integration/baselines/base.py`）

```python
class MemoryPlugin(Protocol):
    name: str
    def retrieve(self, ctx: SceneContext) -> list[RepairHint]: ...       # 唯一读点
    def on_episode_end(self, trace: Trace) -> None: ...                   # 唯一写点
    def on_step_end(self, feedback: StepFeedback) -> None: ...            # 可选，默认 no-op
```

共享循环（`integration/runner.py`）：

```python
def run_episode(policy_gen, memory, env, task, seed):
    ctx = env.reset(task, seed)
    hints = memory.retrieve(ctx)                                   # ① 唯一读点
    policy = policy_gen.generate(task, ctx, hints)
    try:
        obs = Executor(env.api).run(policy, step_cb=memory.on_step_end)  # ② 逐步反馈
        env.state = dict(obs.state)
        trace = Trace.from_success(task, obs, ctx)
    except PiPERError as e:
        trace = Trace.from_error(task, e, ctx)                     # ③ 唯一失败输入
    success = judge(task, env.state)                               # 同一份自动判据
    if ctx.split == "dev":                                         # ④ 防污染：留出集只记录
        memory.on_episode_end(trace)                               # 唯一写点
    check_snapshot(memory.snapshot())                              # 六字段公平性审计
    return success, trace
```

## 9　Linux 运行层：settings 与后端工厂（操作版见 `docs/08`）

本层只负责「在目标 Linux 主机上如何构造执行后端与读取配置」，**不改变**第 3 节 `RobotAPI` 的任何签名，也不新增控制原语。

### 9.1 配置 `src/pasd_life/settings.py`（零依赖）

```python
repo_root() -> Path
load_settings(*, load_dotenv: bool = True) -> Settings
ensure_dirs(s: Settings) -> None
```

优先级：**环境变量 `PASD_*` > `.env` > `configs/default.yaml` > 内置默认**。`.env` 读取器只解析 `KEY=VALUE`，不执行 shell；PyYAML 缺失时静默回退到内置默认。`Settings` 为 frozen dataclass，字段：

`backend, split, seed, repo, home, log_dir, run_dir, artifact_dir, can_interface, can_bitrate, serial_device, llm_model, adapter, allow_real, estop_ack, api_key_present, utf8_ok`。

```python
s.real_guard(confirm_real: bool) -> tuple[bool, list[str]]
s.describe() -> dict          # 可打印，绝不输出 API key 值
```

`home` 默认 `${XDG_DATA_HOME:-~/.local/share}/pasd-life-assist`，在仓库外；禁止在业务代码里写绝对路径。

### 9.2 后端协议 `src/pasd_life/backends/`

```python
class Backend(Protocol):
    def step(self, name: str, **kwargs: Any) -> dict | None: ...
    def observation(self) -> dict: ...

def make_backend(name: str | None = None, *, settings: Settings | None = None,
                 confirm_real: bool = False, scene: dict | None = None,
                 guard_config: GuardConfig | None = None) -> Any
```

| 名称 | 实现 | 行为 |
|---|---|---|
| `mock`（默认） | `MockPiPER(scene)` | 精确保持现有脚手架语义，**不包 guard**（离线路径不变） |
| `mujoco` | `GuardedBackend(MuJoCoBackend())` | 缺 `configs/mujoco/piper.xml` 或 `mujoco` 包时抛 `BackendUnavailable`，**显式失败** |
| `real` | `GuardedBackend(PiperCANBackend(...))` | 需四重确认；SDK 未核对时 `connect()` 抛 `BackendUnavailable` 并列出 6 项核对清单 |

异常类型（`backends/base.py`）：`BackendUnavailable` / `RealHardwareGuardError` / `BackendGuardViolation`。

**真机守卫**：`make_backend("real", confirm_real=True)` 要求同时满足 `backend == "real"`、`PASD_ALLOW_REAL=1`、`PASD_ESTOP_ACK=1`、CLI 显式 `confirm_real=True`；缺一抛 `RealHardwareGuardError`。`PASD_ADAPTER=null` 时 `NullAdapter` 走完整链路但**不发 CAN 帧、不产生关节运动**，输出标记 `DRY-RUN`。

### 9.3 控制层外挂 `backends/guard.py`

```python
@dataclass(frozen=True)
class GuardConfig:
    step_timeout_s: float = 2.0
    workspace_box: tuple[float, ...] | None = None   # 真机标定前不启用
    max_accel: float | None = None

class GuardedBackend:
    def __init__(self, inner, envelope=None, config=None, clock=time.monotonic)
    def step(self, name, **kwargs)      # 白名单校验 → 工作空间盒 → 速度限幅 → 委托 → Watchdog
    def observation(self)               # 再过滤一次 REAL_OBSERVABLE_FIELDS（防污染）
    def estop(self, reason="watchdog")  # 不经过 LLM；调 inner.estop() + EmergencyStop.trigger()
```

限幅上限取 `SafetyEnvelope.max_eef_speed`（0.15 m/s），缺观测不算违规（与第 5 节一致）。**新增后端必须经此包装**，`mock` 离线路径可例外。

### 9.4 约束

- `settings.py` / `backends/` 只能依赖标准库；第三方包一律放 `pyproject.toml` optional extras 且 `try/except ImportError` 优雅降级。
- 不打印密钥、不在 import 时创建目录或连接硬件；`ensure_dirs()` 由 `bootstrap.sh` 显式调用。
- 真机相关的 CAN 位率、VID/PID、SDK 方法名、单位换算都属于**目标机现场核对项**（`docs/08` 第 6 节），仓库只给模板与占位默认值，不得写成既定事实。
