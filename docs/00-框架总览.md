# 00　框架总览（Claude Code 必读）

## 1　一句话

在 Claude Code（code-as-policy）+ PiPER 机械臂平台上，把一次失败蒸馏成**有界、可验证、且安全**的经验单元，用于桌面助餐与取物，并把「精炼性 / 可信性 / 安全性」放进同一套评测口径，形成一篇可投 SCI 的实证论文。

## 2　四层架构与数据流

```
① 策略生成层  用户指令 ──► retrieve_repair(注入 SAFE 修复) ──► Claude Code 生成 run(robot)
                                    ▲                                    │
                                    │                                    ▼
④ 经验蒸馏层  SkillLibrary ── Gate3 ── Gate2 ── Gate1 ── Extractor ◄── 失败 Trace
   (+离线迁移)      │                              （唯一输入）
                    └──────────────► ② 执行-观测层 RobotAPI 五原语 / PiPER / MuJoCo
                                            │
                                            ▼
                    ③ 统一状态与评测层  3D 场景图状态总线 + 运行时能力剖面
                                            │
                                            └──► 失败类型分布 q_t(c) ──► 离线随机化 p_t(θ) ──► 仿真再训练
```

- **①**：`retrieve` 是唯一记忆读点；策略代码只允许调五个原语。
- **②**：成功 → `Observation`；失败 → `Trace(task, error_code, message, features, scene, policy)`，这是 PASD 的**唯一输入**。
- **③**：新增层。把状态表示、时间同步、失败信号、回退触发、日志格式统一（落实《智能体与机械臂融合》七(六) 的接口一致性论述），输出运行时能力剖面与失败类型分布。
- **④**：核心。四要素技能 `⟨σ, C, π, V⟩` + 三闸门状态机 + 离线域随机化闭环。

**闭环性质**：本次会话蒸馏的失败，下一会话 `retrieve` 仍可命中；经验库是累积资产而非一次性日志。

## 3　三闸门经验生命周期

| 闸门 | 输入 | 判据 | 输出状态 |
|---|---|---|---|
| Gate1 `observe_failure` | `Trace` | `Extractor` 生成签名；空签名→REJECTED；`OnlineClusterer.assign` 得身份键 `(stage, error_code, cluster_id)`，半径 0.45；有向取整 `_q_dir` 提取阈值；同身份去重 | `CANDIDATE` |
| Gate2 `verify_gate2` | CANDIDATE + `repair_plan` | 仿真重复 10 次，成功率 ≥0.80；先校验 `repair_plan.fixes == error_code`，不匹配直接拒绝 | `VERIFIED` |
| Gate3 `verify_gate3` | VERIFIED + 真机记录 | 真机连续 ≥8 次成功 + 首次人工确认 + **安全包络通过** | `SAFE` |

`INTENT_AMBIGUOUS`、`IK_UNREACHABLE`、`GRASP_IMPOSSIBLE` 等单臂不可自主修复模式：`propose_repair` 返回 `None`，Gate2/Gate3 必然不晋升——**这是正确行为，不要强行修复**。

C2 的关键机制：**安全包络否决权**——一个修复即便 Gate2 达标，若触发 `MOUTH_APPROACH_UNSAFE` / `FOOD_SPILL` / `SAFETY_VIOLATION`，也不得进入 `SAFE`。

## 4　三条贡献（互相耦合，不要拆成三个独立模块）

- **C1 有界蒸馏**：经验单元是失败签名簇而非 episode/轨迹/文本反思；纯度为 1 时可证 `|B_t| ≤ k`，与 episode 数无关。对应证据：240→9 簇、纯度 1.0、去重率 96%；消融「去 Gate1」复现 211 膨胀。
- **C2 安全可判定签名**：`trigger_task` / `trigger_human` / `trigger_safety` 三维扩展，环节从四类扩为六类（+交互、+安全）；安全进入**晋升判据**，不是事后急停。
- **C3 评测→训练闭环**：`q_t(c) → p_t(θ)`（摩擦、质量、光照纹理、传感器噪声、执行延迟）+ 统一评测协议 S³R、`Δ = SR − S³R`。

耦合关系：C1 的簇分布是 C3 的输入；C2 的安全包络进入 C1 的晋升判据；C3 的协议同时度量 C1/C2。**实现时禁止让三者各自独立跑脚本而互不传递数据**。

## 5　三个「不是」

1. 不是「给系统外挂一个 3D VLM / 评分表 / 随机化模块」（L1 模块替换，无新技术效果）。
2. 不是「复现 TGL / SSS / PRAGMABOT」——那是平台错配；本仓库只做统一 `MemoryPlugin` 下的机制等价代理。
3. 不是「在线学习系统」——策略权重**不做梯度更新**（免训练），仿真参数分布更新严格离线。
