# 02　任务定义与失败签名库

## 1　任务族（`tasks/task_specs.py`）

| ID | 任务 | 主要失败环节 | 参数化难度轴 | 目标错误码 |
|---|---|---|---|---|
| T1 | 细长抓取（圆柱/酒瓶）—抬升—放置 | 执行 | 长宽比 1–12、直径 10–40 mm、质量 20–300 g | `GRASP_SLIP` |
| T2 | 扁平薄片操作（抓取失败→推动替代） | 执行 | 厚度、表面摩擦 | `GRASP_IMPOSSIBLE` |
| T3 | 桌边/障碍侧向趋近抓取 | 规划 | 障碍距 0–60 mm、目标朝向 | `IK_UNREACHABLE` |
| T4 | 低纹理/透明/反光物体抓取 | 感知 | 深度缺失率、光照 | `POSE_LOW_CONFIDENCE`、`DETECTION_FAILED` |
| T5 | 堆叠/遮挡下目标抓取 | 感知 | 遮挡比例 0–70% | `DETECTION_FAILED` |
| T6 | 桌面指定区放置 | 验证 | 目标区尺寸 20–100 mm | `PLACEMENT_OFFSET` |
| T7(OOD) | 未见任务：插孔 / 开抽屉 / 倒水 | 混合 | — | — |
| **A1** | **桌面助餐（三类指令）** | 交互/安全/执行 | 食具形态、盛装量、用户位姿 | `FOOD_SPILL` 等 |
| **A2** | **桌面取物（三类指令）** | 感知/规划/验证 | 遮挡、放置精度、指代模糊 | `OCCLUSION_RETRIEVE_FAIL` 等 |

**每个任务必须能自动判定成功（无需人工标注）并支持自动复位**——真机吞吐瓶颈几乎全在复位。

## 2　三类指令（`tasks/instructions.py`）

沿用安冉等 [4] 协议：简单 **7** 条 / 隐式 **4** 条 / 组合 **13** 条，每条独立 **50** 回合，**30 步上限**，报告均值 ± 样本标准差。

- A1 示例：隐式「帮我喝点汤」、简单「把水杯递到嘴边」、组合「先舀一勺再递过来」。
- A2 示例：简单「把水杯拿给我」、隐式「我有点渴」、组合「把药盒和温水一起放到我右手边」。
- 隐式指令必须经**意图解析**，`intent_confidence < 0.6` → `INTENT_AMBIGUOUS` → 反问澄清，禁止自动晋升或擅自执行。

## 3　A1 桌面助餐

**子目标序列**（`tasks/feeding.py`）：
意图解析 → 目标定位（碗/勺/杯）→ 姿态、盛装量与温度确认 → 可达性与人机距离预检 → 餐具抓取 → 舀取/倾倒 → 送递至口部安全区 → 状态确认 → 撤回与复位。

**状态字段**：`utensil_pose, fill_level, food_temp, human_mouth_pose, min_human_dist, gripper_width, pose_confidence, subgoal_idx, intent_confidence, tilt_angle, eef_speed, contact_force`

| 错误码 | 环节 | 触发条件（有向取整后阈值） | 修复策略 π | 闸门处置 |
|---|---|---|---|---|
| `FOOD_SPILL` | 执行 | `tilt_angle` 超阈值 或 `fill_level` 偏高 | 降倾角、分次少量、更换容器 | Gate2 重跑 → Gate3 安全确认 |
| `UTENSIL_SLIP` | 执行 | `aspect_ratio > 4` 且 `approach == "top"` | 侧夹 + 手腕倾斜 | Gate2 达标晋升 |
| `MOUTH_APPROACH_UNSAFE` | **安全** | `min_human_dist` 低于阈值 或 末端速度超阈值 | 降速 + 重规划接近方向 + 扩大安全区 | **强制 Gate3，未过不晋升** |
| `INTENT_AMBIGUOUS` | **交互** | `intent_confidence < 0.6` | 反问澄清，隐式转具体 | **转人工，禁止自动晋升** |
| `POSE_LOW_CONFIDENCE` | 感知 | `pose_confidence < 0.6` | 重感知 / 换视角 / 补深度 | Gate2 以 `scene_patch` 验证 |
| `IK_UNREACHABLE` | 规划 | `solve_ik` 无解 | 调整餐具摆位或请求协助 | 保持 `CANDIDATE`，**禁止晋升** |
| `SAFETY_VIOLATION` | **安全** | 人机距离/接触力/温度越界 | 停机回退 | 直接 `REJECTED` + 急停 |

> 安全类签名是 C2 的实证载体：`MOUTH_APPROACH_UNSAFE`、`FOOD_SPILL`、`SAFETY_VIOLATION` 必须能被 `SafetyEnvelope.violated()` 直接识别，并作为 `promote()` 的一票否决项。

## 4　A2 桌面取物

**子目标序列**（`tasks/retrieval.py`）：意图/指代消解 → 场景图检索目标 → 可达性与遮挡过滤 → 路径与避障 → 抓取 → 搬运 → 放置到指定区 → 状态确认。
每一子目标带 `completed` 标志并做**顺序校验**，前序未完成不得推进（防止级联失效，对应安冉等图世界模型的状态校验机制）。

| 错误码 | 触发 | 修复 |
|---|---|---|
| `OCCLUSION_RETRIEVE_FAIL` | `occlusion_ratio` 超阈值 | 先移开遮挡物 |
| `GRASP_IMPOSSIBLE` | `target_width > 0.070` | 换夹持策略或换目标（禁止硬夹） |
| `PLACEMENT_OFFSET` | `placement_error` 超阈值 | 重定位再放 |
| `DETECTION_FAILED` | `depth_valid_ratio` 偏低 | 重感知 |
| `SAFETY_VIOLATION` | 人机距离/接触力越界 | 停机回退 |

## 5　PASD 原版四类错误码（仅用于 `baselines/pasd.py`）

`GRASP_SLIP` / `GRASP_IMPOSSIBLE` / `IK_UNREACHABLE` / `POSE_LOW_CONFIDENCE`，环节四类：感知/规划/执行/验证。**不得**在原版 baseline 中出现六类环节或 Gate3。

## 6　签名提取规则（`Extractor`，强制）

1. **只取诊断特征**：阈值只从 `Trace.features` 的白名单字段提取；`Trace.scene` 仅用于在线聚类，**不参与签名阈值生成**。
2. **有向取整** `_q_dir`：`>` 向下取整、`<` 向上取整，为边界样本留余量（修复缺陷 D9）。
3. **空签名不入档**：等价于"在所有条件下都失败"，标记 `REJECTED`，防止退化出万能技能。
4. **四档阈值策略**：`observed`（θ=观测值，自命中 0%）/ `margin`（留余量，自命中 100%）/ `quantized`（分桶去重）/ `split`（按 AUC<0.6 剔除无效维度）。E1 审计用。
5. **匹配语义**：缺项不否决、命中即触发。

## 7　跨任务复用与向上蒸馏

A1/A2 共享 `POSE_LOW_CONFIDENCE`、`GRASP_SLIP`、`IK_UNREACHABLE` 等**与本体无关**的签名，用于 RQ4 零样本迁移验证。
当「细长物体侧夹」「低置信重感知」等低层技能按 `tag` 与 `hits` 频繁协同命中时，可抽象为更高层的组合策略模式（向上蒸馏）。这是**可选扩展**，不得影响主表 A 的公平性。

## 8　安全与伦理

- 真人实验**前**必须先用假人头部模型 / 模拟口部位置完成 Gate3 消融（E4）。
- 急停与 Watchdog 外挂在控制层，不依赖 LLM 生成代码。
- 论文需给出停机协议、最小人机距离阈值来源与用户同意说明。
