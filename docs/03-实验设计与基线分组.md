# 03　实验设计与基线分组（v1.1 规范，权威口径）

> 本文件是 `../实验对比基线实现规范.md` v1.1 的仓库内契约版。冲突时以本文件与 `CLAUDE.md` 的裁决为准。

## 1　为什么必须统一适配

- **记忆结构对比**（No-Memory / TS / Episodic / PASD）：同一策略、同一平台，只换记忆机制 → 可进主表 A。
- **算法范式对比**：没有任何一个原生方法是为「Claude Code 生成 `run(robot)` + PiPER 五原语」设计的；按原生形态各跑各的，差异来自训练数据、算力、动作空间和任务定义，**结论不可解释**。
- 因此所有基线统一「翻译」为 `MemoryPlugin`，只问同一个问题：**若让该范式充当记忆模块，它在「失败后写什么、规划前读什么」上怎么做？** 策略生成器、执行器、成功判据、指标代码保持不变。

## 3　各类基线实现要点

| 基线 | `on_episode_end` 写什么 | `retrieve` 返回什么 | `verified_by` |
|---|---|---|---|
| `pragmabot` | 仅成功时把 STM 摘要写入 LTM；`on_step_end` 用 VLM 成功检测 + 反思 | LTM RAG top-k + 最近 STM 反思 | `none`（反思无验证） |
| `tgl_skill` | 成败都记 Experience Memory 七元组；候选块经五项准入检查入 Skill Block | 块代码 + 经验教训 | `admission_check` |
| `uniskill_proxy` | 只存成功技能代码，无去重、无验证 | top-k 技能代码 + `SkillRequest` | `none` |
| `sss` | 只保留 `trace.repair_verified` 的 accepted repair 片段（本代理**不做梯度更新**，须标注） | 风险低于 τ 时返回技能修复建议 | `vlm_judge` |
| `soar` | VLM 标注后轨迹（训练数据，非经验条目） | 恒 `[]` | `vlm_judge` |
| `armada` | 人工纠正片段 | 失败风险提示 + 回退建议 | `human` |
| `neerl` / `rlingua` | 训练样本 / replay buffer | 恒 `[]`，差异在权重 | `none` |
| `irosa_interface` | — | 参数化 KMP 工具接口对照 | 不参与 SR 主表 |

PASD 与 `pasd_full` 的 Gate1/Gate2/Gate3/`retrieve_repair` **全部折叠进** `retrieve` / `on_episode_end`；`on_step_end` 为空实现。

## 4　公平性控制清单（16 条，`scripts/fairness_audit.py` 逐项自检）

| # | 控制项 | 做法 |
|---|---|---|
| 1 | 同一动作空间 | 全部经白名单五原语，禁止基线自带控制接口 |
| 2 | 同一策略生成器 | 同一 Claude Code 配置、system prompt 模板、temperature |
| 3 | 同一任务与划分 | 同一 T1–T7/A1/A2，同一 seen/unseen 划分 |
| 4 | 同一成功判据 | 同一 `judge()`、30 步上限、自动判定 + 自动复位 |
| 5 | 同一 episode 预算 | 每方法 200 episode 学习曲线；A1/A2 三类指令各 50 独立回合 |
| 6 | 同一 LLM 调用与 token 预算 | PRAGMABOT/SSS/TGL/PASD 的失败后生成次数与 `max_tokens` 一致 |
| 7 | 同一数据预算 | 任一基线用 N 条示教，其余须可等量访问同 N 条 |
| 8 | 同一注入长度 | `retrieve` 返回上限 k 与截断策略一致 |
| 9 | 同一防污染约束 | 禁仿真真值；dev 可写库、heldout 只记录 |
| 10 | 同一随机种子序列与复位脚本 | `configs/seeds.yaml` + `scripts/reset_scene.py` |
| 11 | 同一指标计算代码 | 全部走 `integration/metrics.py` |
| 12 | 同一硬件/仿真标定 | 摩擦与夹持力标定冻结后共用 |
| 13 | **训练/免训练分组隔离** | `snapshot()["requires_training"]` 决定 C1/C2，分表显著性 |
| 14 | **FM/VLM 判官调用预算对齐** | 成功检测、修复判定、outcome check、Gate2 仿真统一记账 |
| 15 | **人工监督预算对齐** | ARMADA 接管、TGL 示教、PASD Gate3 首次确认分别列明折算 |
| 16 | **经验写入时机对齐** | STM(episode 内) vs LTM(完成后)、成功才写 vs 成败都写，须在表中标注 |

第 6、7、13 条最易被忽略。

## 5　指标体系与统计口径

- 任务：SR（30 步内完成占比）、ET（指令到动作序列结束耗时）、CR（已完成子目标占比）。
- 蒸馏：FTR（失败转 VERIFIED 修复比例）、去重率、簇纯度、`|B_t|`、假晋升率、precision@k、误触发率、蒸馏时延、存储增量。
- 过程：中间状态校验通过率、失败位置/类型分布、恢复尝试次数、局部重规划成功率。
- 安全：最小人机距离、最大接触力、急停/中断次数、洒漏率、安全违规晋升拦截数。
- 迁移：SRCC、仿真—真实成功率落差、长尾失败率、收敛所需真实样本数。
- 本文新增：`S³R`、`Δ = SR − S³R`。
- 统计：配对 bootstrap 95% CI 或 Wilcoxon signed-rank，多方法比较 Holm 校正；所有指标由同一份 `metrics.py` 计算；公开任务配置、种子表、复位脚本、日志 schema。

**`verified` 口径**：按 `verified_by` 分别统计；「假晋升率」只对**存在晋升状态机**的方法计算，其余记 `N/A` 并注明机制原因，**不要填 0 充数**。

## 6　最小实验矩阵（E1–E7）

| 实验 | 目的 | 方法 | 主指标 | 状态 |
|---|---|---|---|---|
| E1 签名审计 | C1 前提 | 四档阈值策略，240 次失败 | 簇数/纯度/去重率 | **已复现** 240→9 簇、纯度 1.0、96% |
| E2 库规模收敛 | C1 主结论 | 本文/TGL 式/SSS 式/去 Gate1/No-Memory，每方法 200 episode×3 seeds | `\|B_t\|` 曲线、FTR、precision@k | 协议 + 预期 |
| E3 双任务端到端 | C1+C2+C3 | 主表 A 全部免训练基线 | SR、S³R、ET、CR、Δ | 协议 + 预期 |
| E4 安全消融 | C2 主结论 | 去 Gate3 / 完整系统（假人头部先做） | 最小人机距离、危险接近、急停、误喂 | 协议 + 预期 |
| E5 泛化 | RQ4 | seen/unseen 物体、跨任务签名复用 | 零样本 SR、簇复用率 | 协议 + 预期 |
| E6 迁移闭环 | C3 主结论 | 自适应随机化 vs 固定均匀采样，3 轮 | SRCC、真实域落差、长尾失败率 | 协议 + 预期 |
| E7 跨范式定位 | 划界 | 副表 C2（标注预算） | 只报趋势 | 协议 + 预期 |

**不得把「预期趋势」写成实验结果**；代码里不允许预填成功率。

- 主结论只由主表 A/B 支撑；C1/C2 表述为「在统一记忆插件接口下的机制等价参照」。
- 除非真正移植原实现，**不得写「复现了 TGL / SSS / PRAGMABOT」**。
- 必须正面引用并划界 TGL（arXiv:2608.17209）与 SSS（arXiv:2609.38178），二者均早于本方案记录时间。
- 必须报告 SSS 的修复成功率 0.70–0.77 作为参照，不回避。
